# Feature: Code-Contextual Outreach Generator

## Problem

Developers are constantly spammed by recruiters with copy-pasted messages that show zero understanding of their actual technical skills. Consequently, response rates to typical recruiting cold messages are under 10%. 

Developers ignore messages that:
1. Don't mention their real projects or open-source libraries.
2. Ask for skills they don't have or have never coded.
3. Sound generic, corporate, or overly pedagogical.

## Goal

Provide a recruiting copywriter utility ("Outreach Copilot") that reads a builder's public code footprint (recent commits, star repositories, architecture choices) and generates an ultra-personalized, short cold outreach message. 

This message directly references a technical aspect of their work (e.g. "I saw your custom WebGL renderer in your `fractal-gen` repository...") and connects it seamlessly to the recruiter's open role.

## Non-goals

- **No automated sending.** BuilderHunt does not send emails or DMs directly; it only drafts them. The recruiter must copy, review, and send the message manually.
- **No candidate-spammer generation.** We enforce limits (e.g., max 10 drafts per day) to prevent users from scraping and generating spam lists.

## User stories

1. **As a recruiter**, in the builder details view, I want to open the "Outreach Generator", enter a short description of my open role (or paste a job link), and receive a custom draft message.
2. **As a recruiter**, I want to choose different message tones: `Casual Developer` (direct, lowercase, peer-to-peer), `Professional` (polite, business-first), and `Technical Deep Dive` (deeply analytical about their code).
3. **As a recruiter**, I want to edit the generated draft directly in the browser and copy it to my clipboard with one click.

## Technical architecture

### 1. Context Collection
When the recruiter requests a draft for `builderId`:
- Fetch the developer's bio, top repositories, recent commits, and blog posts.
- Aggregate their main programming languages and framework topics.
- Accept the recruiter's input: `jobTitle` (e.g. "Senior Rust Engineer"), `companyName` (e.g. "Supabase"), and `jobDescription` (brief summary of requirements).

### 2. Prompt Engineering & Vetting
- Call the Gemini API (`gemini-2.5-flash`) with a system instruction that strictly forbids generic outreach cliches (like "I was impressed by your profile" or "I have an exciting opportunity").
- **Core instruction**: The message must start by referencing a specific project or technical highlight from the builder's profile. It must explain *why* that specific project proves they are a fit for the role.
- Constraint rules:
  - Keep the length under 150 words.
  - Never mention generic skills unless linked to an active project.
  - Provide a clear, low-pressure call to action (e.g., "Are you open to a brief chat next week?").

### 3. Tone Configurations
- **Casual Developer**: Lowercase, conversational, peer-to-peer.
- **Professional**: Capitalized, structured, business-polite.
- **Technical Deep Dive**: Technical vocabulary, asking specific architectural questions based on their commits.

## Data shape

Draft generation payload:

```ts
export interface SourcingOutreachRequest {
  builderId: string
  jobTitle: string
  companyName: string
  jobDescription?: string
  tone: 'casual' | 'professional' | 'geek'
}

export interface SourcingOutreachResponse {
  subject?: string
  body: string
  referencedProject: string // name of the repository/article referenced
}
```

## UX integration

- Add an "Outreach Copilot" panel inside the builder profile detail sheet.
- Include input text boxes for job details.
- Add a toggle selector for Tone.
- Render the output in a styled markdown text block resembling an email compose window.
- Add a "Copy to Clipboard" button with a tick micro-animation.

## Success metrics

- **Conversion**: Outreach messages generated by the tool yield response rates > 35% (a 3x+ improvement over standard industry sourcing).
- **Recruiter Productivity**: Recruiters write highly personalized pitches in under 30 seconds rather than spending 15 minutes reviewing candidate codebases.
